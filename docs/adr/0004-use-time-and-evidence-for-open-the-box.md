# Use time and evidence for Open the box

The earlier batch game rewarded a fixed middle setting. This prototype needs a changing reason to inspect while keeping one delivery score.

## Considered options

- Reward unchecked loads with a multiplier. This rewards avoiding assurance directly.
- Subtract points for harmful gifts. The score would stop meaning correct gifts delivered.
- Reveal every fault immediately. Sampling would provide no new information.

## Decision

Use a 90-second night and six-gift loads. Sampling consumes two seconds. Shipping consumes three seconds; holding remakes the load in ten. Unsafe helmet deliveries trigger a twelve-second recall delay, reducing remaining delivery opportunities. A round-four update increases faults until rolled back. Rollback changes future production; the current load retains its original contents.

Model occasional correlated batch faults, with different likelihoods by gift type. Generate each load from the seed and load number, independently of how many boxes the player opens. The default seed is fixed and a seed query value supplies a repeatable alternative. Reveal contents only on inspection or delivery. Choose the closing lesson from actions taken.

## Consequences

The score always counts actual correct gifts. Checking has an opportunity cost and consequential faults cost more time. Players can compare sampling strategies against identical loads. The fixed update is a short teaching scenario; repeat players may learn its timing.
